--------------------------------------------------------------------------------
1. ROUTING
--------------------------------------------------------------------------------
The original app had NO router. App.tsx used a useState string compared on every
render, so any deep link or refresh landed on the home page.

react-router-dom was added (a deliberate deviation from "only add these libs" -
it was the one extra library required to make routes real) and App.tsx is now a
BrowserRouter with an <Outlet /> shell.

Important detail: every existing page takes an onNavigate(path) prop and
addresses other pages by their shipped filename ("about-us.html"). Rather than
rewrite 5 pages and every link inside them, App.tsx has a withNav() adapter
component that injects a router-backed onNavigate with the identical signature.
All original copy, links and cross-references are untouched.

All nine shipped routes are preserved:
  /solartechsystems.html  /about-us.html     /our-clients.html
  /gallery-blog.html      /contact-us.html
  /solar-power-plant.html /solar-rooftop.html
  /33kv-transmission-line.html /33-11kv-substation.html
Plus /index.html and a catch-all that redirect home.

src/hooks/useSiteNav.ts is the bridge. It also handles in-page anchors
("#services") by scrolling with Lenis, offset -96px to clear the fixed header.

2. SCROLL: LENIS + GSAP
--------------------------------------------------------------------------------
One Lenis instance, created above the router so it survives navigation and its
ScrollTrigger is never destroyed and rebuilt.

src/lib/motion/lenis.ts
  - singleton pattern, duration 1.1
  - lenis.on('scroll', ScrollTrigger.update)   <-- required sync
  - driven from gsap.ticker (RAF)
  - gsap.ticker.lagSmoothing(0)
  - returns null under prefers-reduced-motion, so native scrolling is untouched

src/lib/motion/gsap.ts
  - single registration point for ScrollTrigger + CustomEase, guarded against
    double-registration
  - every animation is built inside gsap.context() via the useGsapContext hook
    and reverted on unmount. This is what makes React StrictMode's double-mount
    safe (enabled in main.tsx deliberately, to surface leaks in dev).

Layout.tsx triggers ScrollTrigger.refresh() on window load, on document.fonts.ready
and in a requestAnimationFrame after every pathname change. The last one matters:
a client-side route swap replaces the whole Outlet subtree, so triggers created
inside the old page would otherwise keep stale measurements.


--------------------------------------------------------------------------------
3. THE SUN / SKY SYSTEM
--------------------------------------------------------------------------------
The signature element. A scroll-linked day cycle: pre-dawn -> dawn -> morning ->
noon -> afternoon -> late afternoon -> dusk.

src/components/SunLayer.tsx
  - mounted once in Layout, variant="home" | "inner"
  - a single GSAP timeline scrubbed across the whole document
  - animates CSS custom properties (--sky-top, --sky-bottom, --sun-disc,
    --sun-glow-strength, --sun-x, --sun-y, --sun-scale), not element styles
  - declared with @property in index.css so they interpolate smoothly
  - the sky and sun are separate fixed layers behind everything at z-index -20/-10

This is the single source of truth for time-of-day. No other component animates
the sun.


--------------------------------------------------------------------------------
4. WEBGL HERO SCENE  (src/components/3d/)
--------------------------------------------------------------------------------
Lazy-loaded, device-gated, and deliberately NOT in the critical path.

  SunOrb.tsx        - emissive disc + corona + additive glow sprite. The glow
                      texture is generated on a canvas at runtime, so no image
                      asset is shipped.
  PanelArray.tsx    - 128 modules in ONE InstancedMesh (single draw call), with
                      a gentle terrain sine offset so the field is not a plane.
  EnergyParticles   - 160 points in one <points> object, positions rewritten per
                      frame, converging from the array up to the grid.
  SolarScene.tsx    - the Canvas, transparent (alpha: true) so the CSS sky is
                      the backdrop, NoToneMapping, dpr capped [1, 1.6], and an
                      IntersectionObserver that flips frameloop to "never" when
                      the hero leaves the viewport.

GATING (all must be true to mount):
  - hasFinePointer()        - touch devices skip it entirely
  - !prefersReducedMotion()
  - canUseWebGL()
Gated-out devices get the CSS sun instead, which is already scrubbed and free.

ONE SUN, NEVER TWO: when the scene mounts it sets data-webgl="sun" on <html>,
and index.css hides the CSS .sun-layer. On unmount the attribute is removed and
the CSS sun returns.

When mounted it also sets data-sun="on", which dims the page-level blueprint
texture so it reads as surface detail rather than a pattern fight.

Verified in the build output - three.js is in its own chunk, not the main one:
  dist/assets/index-*.js          529 kB   (168 kB gzip)  <- initial
  dist/assets/SolarScene-*.js     915 kB   (243 kB gzip)  <- lazy, deferred

@react-three/drei was installed then removed: nothing imported it, and R3F +
three alone covered every requirement. @types/three added as a dev dependency.

--------------------------------------------------------------------------------
6. HORIZONTAL SCROLL
--------------------------------------------------------------------------------
The 4 service cards run as a pinned horizontal track on desktop. On touch and
tablet it is NOT pinned - it becomes a native overflow-x scroll-snap carousel
with zero JS animation. This is what prevents the horizontal jank the brief
warns about, and the scroll distance is measured from the live track so it
cannot desync on resize or image load.
