================================================================================
LIBRARY INVENTORY: WHAT IS INSTALLED, WHAT IS ACTUALLY USED, AND WHERE
================================================================================

This section is a map of every third-party package in package.json, what it
actually does in this app, and the exact files that import it. The central
rule the codebase follows: GSAP, Lenis, ScrollTrigger and the design tokens
are NEVER imported from node_modules directly by a component. Everything goes
through src/lib/motion/, which registers plugins exactly once and owns the
single Lenis instance.

gsap/ScrollTrigger
  WHAT:      Binds animation timelines to scroll position and recomputes
             trigger start/end on refresh. This is what makes the whole site
             scrub correctly after a route change.
  WHERE:     Imported ONLY in src/lib/motion/gsap.ts, registered once, and
             re-exported. Direct consumers:
               src/components/Layout.tsx        -> ScrollTrigger.refresh() on
                                                     load, fonts.ready, popstate
                                                     and on the next rAF after
                                                     every pathname change
               src/components/SunLayer.tsx      -> master scrub trigger on <html>
               src/components/motion/ScrollProgress.tsx
               src/components/motion/SectionIndicator.tsx
               src/components/motion/PageTransition.tsx -> refresh on settle
               src/lib/motion/lenis.ts          -> lenis.on('scroll',
                                                     ScrollTrigger.update)
  CRITICAL:  Layout.tsx and PageTransition.tsx coordinate through
             document.documentElement.dataset.transitioning. PageTransition
             clears leftover transforms before refreshing, because a transformed
             ancestor flips ScrollTrigger's pinType from "fixed" to "transform".

gsap/CustomEase
  WHAT:      Custom cubic-bezier easing registration.
  WHERE:     Imported and registered in src/lib/motion/gsap.ts only. Registered
             alongside ScrollTrigger and useGSAP so no component can create a
             custom ease before the plugin exists. No component currently
             instantiates a CustomEase — the ease strings actually used are the
             stock ones in src/lib/motion/tokens.ts (power3.out, expo.out, ...).

@gsap/react 2.1.2  (useGSAP)
  WHAT:      React binding that runs an effect inside a gsap.context() and
             reverts everything on unmount. This is the mechanism that makes the
             app leak-free under StrictMode double-mounting.
  WHERE:     src/lib/motion/gsap.ts (register + re-export), then wrapped by
                 src/hooks/useGsapContext.ts -> useGsapContext(), the hook 14
               components actually call:
                 components/SunLayer.tsx
                 components/hero/SunriseHero.tsx, heroUtils.ts
                 components/svg/EnergyFlow.tsx (uses useGSAP directly)
                 components/3d/SolarScene.tsx (uses useGSAP directly)
                 components/motion/Reveal, RevealText, AnimatedCounter,
                                    ImageReveal, HorizontalScroll, Parallax,
                                    PinnedSection, ScrollProgress,
                                    SectionIndicator
  NOT USED:  components/Navbar.tsx, components/motion/PageTransition.tsx,
             CustomCursor.tsx and RaysLoader.tsx drive plain gsap timelines in
             useEffect with an explicit kill in the cleanup instead.
             useGsapContext is also the only caller of the revertOnUpdate:true
             option, so those four do not get config-change reversion.

lenis 1.3.26
  WHAT:      Smooth/inertial scrolling, driven by the GSAP ticker so it and
             ScrollTrigger can never disagree about scroll position.
  WHERE:     src/lib/motion/lenis.ts   -> the only `import Lenis from 'lenis'`.
             Module-level singleton: initLenis(), destroyLenis(), getLenis(),
             scrollToTop(). syncTouch:false keeps native touch momentum on
             mobile.
             src/hooks/useLenis.ts       -> creates/destroys it for the app
             lifetime, mounted ONCE in src/components/Layout.tsx above <Outlet/>
             src/hooks/useSiteNav.ts     -> getLenis() for anchor scrolling
             src/components/motion/PageTransition.tsx -> scrollToTop() on
             every route change
  NOTE:      initLenis() returns null under prefers-reduced-motion, which is how
             smooth scroll is disabled for the whole app in one place.

tailwindcss 4.3.3  +  @tailwindcss/vite 4.3.3
  WHAT:      Utility CSS. There is no tailwind.config.js — this is Tailwind v4
             CSS-first config, so the design system lives in the stylesheet.
  WHERE:     @tailwindcss/vite is a Vite plugin in vite.config.ts:12.
             tailwindcss itself is imported in exactly one place:
               src/index.css:1   -> @import "tailwindcss";
             src/index.css (1291 lines) then holds @theme at line 89 (the
             blue / rose / slate / ink / sun token scales) and 17 @keyframes
             blocks (slowDrift, sun-rotate, hero-sun-spin, hero-mote-drift,
             floatWave, pulseGlow, shimmer-drift, ...). Components consume the
             tokens as classes, e.g. bg-ink-950, text-dawn-200, font-display.
             Motion-side custom properties written by GSAP (--sky-top, --sun-x,
             --sun-glow-strength, --hero-sun-x/y) are also declared here and are
             what makes the sun render with JavaScript disabled.

--------------------------------------------------------------------------------
5. THE IMPORT RULES THIS INVENTORY IMPLIES
--------------------------------------------------------------------------------

  1. Animations import gsap / ScrollTrigger / useGSAP ONLY from
     src/lib/motion/gsap.ts. Importing from 'gsap' anywhere else risks using a
     plugin before it is registered, and bypasses the single-registration guard.

  2. Every animation lives in useGsapContext() (or a raw useGSAP/gsap.context
     with an explicit kill) so it is reverted on unmount. src/main.tsx keeps
     StrictMode on deliberately: the double mount is the test that leaked
     ScrollTriggers and doubled timelines would fail.

  3. One Lenis instance, created by src/lib/motion/lenis.ts, mounted once in
     Layout ABOVE <Outlet/>. Page-scoped code asks for it with getLenis(); it
     never creates one.

  4. Durations, eases, breakpoints, sky phases and reduced-motion fallbacks come
     from src/lib/motion/tokens.ts. No magic numbers in components.

  5. prefers-reduced-motion is read through src/hooks/useReducedMotion.ts (live,
     re-rendering) or src/lib/motion/utils.ts (imperative, for useFrame), never
     by calling matchMedia inline in a component.

  6. Tailwind tokens are CSS variables in src/index.css. The GSAP-driven ones
     (--sky-*, --sun-*, --hero-sun-*) are written to :root by SunLayer and
     SunriseHero, and the CSS consumes them — so the sun still renders with no
     JavaScript.

================================================================================
DATA FLOW: ONE NAVIGATION, END TO END
================================================================================

    user clicks "Our Clients" in the Navbar
      |
      1. <a href="our-clients.html"> with onClick -> e.preventDefault()
      2. useSiteNav().navigate('/our-clients.html')
      3. React Router matches Route, swaps the Outlet subtree
      |     - ClientsPage mounts, its own contexts register
      |     - previous page unmounts, its contexts revert  <-- no leaks
      |     - Navbar, SunLayer, Lenis, PageTransition all UNTOUCHED
      4. Layout: useDocumentMeta writes <title> + description from ROUTE_META
      5. Layout: rAF -> ScrollTrigger.refresh() against the new DOM
      6. PageTransition plays the sheet wipe
      7. Lenis is already at scroll 0, so the new page starts at the top
         without a second scroll reset fighting the transition

Nothing in steps 1-7 tears down a global system. That is the whole point of the
mounting arrangement in section 2.
